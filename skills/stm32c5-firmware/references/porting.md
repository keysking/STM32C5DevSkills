# 移植驱动到 C5

仅适用于移植或集成任务。以源库接口、目标硬件和用户功能为边界，不要求添加全部阻塞/中断/DMA 路线。

1. 读源库许可、API 和硬件假设，确定只读/读写协议、时序和错误返回；保留原许可。
2. 列出需要适配的 GPIO、I2C/SPI/UART、时间、内存和并发接口。优先保留简洁的固定接口，不为单个外设增加无需求的控制器注册架构。
3. 按[HAL2 接口](hal2-ll.md)重写板级适配；不将 F1/HAL1 的 handle、DMA Channel 常量或时钟函数复制进 C5。
4. 实现需求指定的传输方式；协议故障可用隔离的阻塞测试缩小范围，不为已有异步驱动强加另一套实现。需要 IT/DMA 时，异步接口要明确 Busy、完成通知、缓冲区有效期和失败恢复。
5. RTOS 下同一总线通过互斥量或专用总线任务串行化；ISR 使用允许的通知/队列接口，不获取 mutex。
6. 新源文件加入构建目标，先验证链接和资源，再验证器件行为。

移植检查表：

| 旧假设 | 在 C5 上重新确认 |
| --- | --- |
| HAL1 `I2C_HandleTypeDef` | HAL2 `hal_i2c_handle_t`、MASTER 接口和地址格式 |
| SPI length 是字节 | 实际数据帧宽度与 `count_packet` |
| RX callback 只有 handle | HAL2 的长度、事件类型及注册宏 |
| 固定 DMA 通道 | CubeMX2 实际分配与请求 |
| `HAL_Delay` 可在任何地方调用 | tick 来源、ISR 优先级和 RTOS 阻塞需求 |
| 栈上临时发送缓冲 | DMA 结束前必须保持有效 |
| 写 `main.c` 注释区能保留 | 执行暂存生成、差异合并 |

适配 I2C 地址时明确上下层使用 7 位值还是已移位值，只在约定边界转换一次。设备控制字节、寄存器布局和数据格式来自真实器件协议。需要异步刷新或批量传输时区分“启动成功”和“传输完成”，不自动增加 DMA。

完成交付说明适配文件、配置前提、调用示例、资源占用和实际硬件测试；没有硬件时明确仅完成接口与构建检查。
