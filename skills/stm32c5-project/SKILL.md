# STM32C5 工程

按本次需求选择下列场景及参考章节，不把整篇资料当成执行清单。命令中的型号、引脚、数值和名称用于说明语法，须替换为真实需求及当前工程的值；只执行所选操作和必要依赖，查询任务不顺带修改配置。

1. 从 `.ioc2`、设备头文件、启动文件、链接脚本和构建参数确认完整 C5 型号；不凭文件夹名称选芯片。型号未知时先询问型号；现有工程可以继续只读检查。
2. 新建默认 CubeMX2 + HAL2 + CMake/Ninja/GCC + 裸机。按[创建命令参考](references/create.md)建立实际目标工程，只有任务需要才添加外设或 RTOS；型号与封装约束见[型号边界](../stm32c5-env/references/c5-basics.md)。
3. 接手工程或从例程开始，读[工程识别与其他入口](references/existing-and-examples.md)。已有工具链、布局、RTOS API 保持原选择，除非任务要求迁移。
4. `.ioc2` 是复合工程容器，使用 `cube mx` 读写；不做 JSON 反序列化后整体重写。
5. 引脚和外设任务进入[配置技能](../stm32c5-configure/SKILL.md)。生成前必须读[安全重新生成](references/regenerate.md)：导出到新的空目录，检查完整差异并合并。
6. 需要交付可构建工程时用[构建步骤](../stm32c5-build/references/build.md)取得 ELF，再说明是否具备烧录和功能测试条件。

按任务判断完成：识别任务给出工程事实；创建/维护任务确认配置已保存、依赖可恢复且应用保留；要求可构建交付时验证实际构建。创建工程不自动授权烧录连接中的其他板卡。
